# ADR-001: LitmusChaos for Kubernetes Chaos Engineering

## Status
Accepted

## Context
The Phenotype platform requires chaos engineering capabilities to:
1. Validate system resilience
2. Test failure recovery mechanisms
3. Ensure high availability guarantees
4. Identify weak points before production

## Decision
Adopt LitmusChaos as the primary chaos engineering platform because:
1. Kubernetes-native architecture
2. Rich experiment library
3. GitOps integration
4. Active community
5. Enterprise features via ChaosCenter

## Implementation Strategy

1. **Experiment Definition**: Custom resources for chaos experiments
2. **Workflow Integration**: Chaos experiments as part of CI/CD
3. **Safety Controls**: Abort conditions and blast radius limits
4. **Observability**: Integration with Prometheus and Grafana

```yaml
apiVersion: litmuschaos.io/v1alpha1
kind: ChaosEngine
metadata:
  name: phenotype-pod-failure
spec:
  appinfo:
    appns: default
    applabel: "app=phenotype-api"
  experiments:
    - name: pod-delete
      spec:
        components:
          env:
            - name: TOTAL_CHAOS_DURATION
              value: '30'
```
