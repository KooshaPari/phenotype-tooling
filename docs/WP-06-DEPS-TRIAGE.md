## 1. Scope

- **122 advisories** open on `main` at Phase 2 close (1 critical · 34 high · 64 moderate · 23 low).
- This WP does **not** patch all of them. It establishes the **process + scaffolding** to triage, owner, SLA, and review so that no advisory stays open beyond its tier.

## 2. SLA Tiers

| Tier | Severity | Fix-by | Owner accountability | Default reviewer |
|---|---|---|---|---|
| **P0 — emergency** | critical | 24 h from alert creation | Direct owner | @KooshaPari |
| **P1 — high** | high | 7 d from alert creation | Crate owner | @KooshaPari |
| **P2 — moderate** | moderate | 30 d | Crate owner | @KooshaPari |
| **P3 — low** | low | 90 d | Crate owner | @KooshaPari |
| **P4 — definable-wontfix** | any | next minor release | Maintainer judgment | @KooshaPari |

SLA escalation rule: if an open P0 has not been touched in 12 h, it gets re-assigned to `@KooshaPari` automatically via workflow triage.

## 3. Triage Process

1. **Receive** — dependabot bot creates a `dependencies` + `security` labeled PR. The workflow `governance/ci-deps-triage.yml` (added in WP-06) attaches additional metadata (`severity`, `ecosystem`, `reachable`).
2. **Categorize** — within 24 h of PR open, a triager fills the issue template (template at `ISSUE_TEMPLATE/deps-triage.yml`) which captures: severity, fix-version, reachability evidence (path-reachable / dev-only / TS-only / unmaintained), owner, SLA tier.
3. **Plan** — groups (already configured for github-actions) bundle weekly; for cargo, separate PRs per major-version-bump. `weekly` schedule keeps noise low.
4. **Patch or backport** — either bump the dependency or apply a vendor patch (`bin/vendor-patch.py`). For P0/P1, request dry-run CI immediately; do not wait for monday.
5. **Close** — merge the dependabot PR; the issue closes automatically; the deps-vuln ledger (see §4) records the result.
6. **Reassess** — weekly review on Mondays (configured); P2/P3 automatic re-promotion if a higher-tier replacement is published upstream.

## 4. Deps Vulnerability Ledger

A new top-level file `SECURITY_DEPS_LEDGER.md` records all open and resolved advisories in a single greppable location (machine-readable for WP-09 dashboards).

The ledger is regenerated by `.github/workflows/deps-ledger.yml` on every dependabot PR merge and on Mondays. The schema is:

```yaml
- advisory_id: RUSTSEC-2024-XXXX         # or GHSA-xxxx, CVE-xxxx
  package: {name}:{version}
  severity: critical|high|moderate|low   # lowercase
  reachable: bool                        # cargo's `cargo audit` reachable path
  fix_version: {name}:{version}
  owner: @handle
  sla_tier: P0|P1|P2|P3|P4
  status: open|in_progress|patched|wontfix|backported
  opened_at: YYYY-MM-DD
  closed_at: YYYY-MM-DD
  pr_url: https://…
```

(Implementation of this file lives in WP-06-T1.)
